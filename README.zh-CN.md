# A Better Taiko Hiroba

[English](README.md)

一套鼓众广场（donderhiroba.jp，日服）的客户端工具：在桌面端、安卓端或命令行里查看和修改自己的太鼓
游玩数据——成绩、资料、小咚、各项设定，不用再在原站上绕来绕去。它跑在你自己的设备上，直接和广场
打交道，你的数据不经过我们的任何服务器。

## 它将会做什么

下面一项都还没做完。每完成一项，对应的功能说明就随它一起写进来，放在实现它的那条分支上。

**看自己的游玩数据**

- [ ] 用万代南梦宫 ID 登录，并且一直保持登录
- [ ] 所有曲目、所有难度：皇冠、评价、分数、打击数、游玩选项
- [ ] 资料、小咚、称号、段位
- [ ] 近期游玩记录，不用再一个分类一个分类地翻

**修改广场设定，比在原站上顺手**

- [ ] 称号——连同一个个部件拼出来的那种
- [ ] 玩家名字
- [ ] 小咚的服装和配色；原站不声不响就替你改掉的那些规则，这里会先讲清楚
- [ ] 游戏设定
- [ ] 收藏曲目，以及广场上那首「大好きな曲」
- [ ] 改之前能预览，改完能还原

**数据留在自己手上**

- [ ] 一个本地数据库，断网也能照翻
- [ ] 多账号——一个万代南梦宫 ID 最多能绑三张卡
- [ ] 同步是增量的、有额度的、断了能接着跑，曲库再大也不会一口气猛拉

**在哪些端上跑**

- [ ] 命令行
- [ ] 桌面端
- [ ] 安卓端
- [ ] iOS——后期
- [ ] Web——后期；也只有它可能需要配一个自己的小服务器
- [ ] 一套可编程 API，让脚本驱动的核心和各端用的是同一个
- [ ] 界面支持英文、日文、中文

**以后再说**

- [ ] 一键把成绩传到菌菌——优先级最低，它的 API 是个黑盒

## 它怎么工作

一个无头核心，外面套一层薄前端：

1. **WebView** 负责登录广场，把会话 cookie 交出来。
2. 各平台的 **transport** 拿着这个 cookie 去抓广场页面。桌面、安卓、命令行都能直连；浏览器受同源
   策略限制做不到，所以 Web 端是唯一允许配小服务器的地方。
3. **核心**把每个页面解析成结构化记录，存进 SQLite。
4. **同步引擎**管抓取的节奏：一次只发两三个请求、彼此隔开、没变过的就跳过。

数据按太鼓番归类，几个账号可以并存，也都能离线翻看。会话 cookie 交给各平台自己的安全存储，绝不会
以明文写进数据库。

## 几句实话

**非官方。** 本项目和万代南梦宫娱乐没有任何关系，也未获其背书。太鼓の達人、ドンだー広場都是人家的。

**默认客气。** 广场是别人的服务器。抓取有意放慢，而且只抓变过的部分；对方一限流就退回去等。
「多抓一点」得你开口，不会自己发生。

**账号是你的，主意也得你拿。** 这套工具以你的身份登录，动的是你真实的太鼓资料。每次改动之前它会
告诉你要做什么、之后怎么改回去——但账号终归是你的，后果也一样。

## 目录结构

```text
packages/core   无头核心：领域模型；广场常量与 URL 构造；抓取节流；解析器；
                以及 Storage / Transport / SecureCredentials 接口背后的 bun:sqlite 存储。
packages/i18n   翻译 catalog（en / ja / zh）和一个很小的翻译运行时。
apps/cli        Bun 命令行客户端。
```

## 约定

- 源码只用英文，标识符和注释都一样。要给用户看的文字一律以 key 的形式放在 `packages/i18n`。
- 代码按 `tim-style-code` 写，文档按 `plainspoken-docs` 写。
- 提交遵循 Conventional Commits：一次只做一件事，标题一行。

## 开发

需要 [Bun](https://bun.sh) 1.3 或更新的版本。

```bash
bun install
bun test
bun run typecheck
```
